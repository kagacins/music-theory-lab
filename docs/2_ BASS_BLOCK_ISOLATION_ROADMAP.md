# Bass Block Isolation & Notation UX Overhaul

**Document Created:** December 30, 2025
**Status:** Planning Phase
**Priority:** High - Addresses core usability issues

---

## Executive Summary

This document outlines a comprehensive overhaul of the bass clef editing system and notation toolbar UX. The primary goals are:

1. **Isolated Bass Blocks** - Each chord's bass section operates independently, preventing cross-block corruption
2. **Clear Selection Model** - Users always know what region they're editing
3. **Simplified Toolbar** - Progressive disclosure reduces cognitive load
4. **Resolved Click Ambiguity** - Clear treble vs bass targeting

---

## Part 1: Isolated Bass Block Architecture

### Current State (Problems)

```
CURRENT BASS MODEL:
┌──────────────┐┌──────────────┐┌──────────────┐
│ Block 0 (C)  ││ Block 1 (Am) ││ Block 2 (F)  │
│ [notes...]   │→│ [notes...]   │→│ [notes...]   │
└──────────────┘└──────────────┘└──────────────┘
                ↑
         Edits can bleed across boundaries
         Shift operations work on measures, not blocks
         "Building block is full" errors when data desyncs
```

**Current Issues:**
- Bass shift operations use `noteEditor.js` measure-based approach, not block-based
- Edits in one block can affect adjacent blocks
- No clear boundary enforcement
- Confusing "building block is full" errors when measure data doesn't match block expectations
- `Shift+Arrow` insert doesn't work properly in bass clef

### Proposed State (Solution)

```
PROPOSED BASS MODEL:
┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│ Block 0 (C)  │ │ Block 1 (Am) │ │ Block 2 (F)  │
│ [isolated]   │ │ [isolated]   │ │ [isolated]   │
└──────────────┘ └──────────────┘ └──────────────┘
      ↑               ↑               ↑
   HARD           HARD            HARD
   BOUNDARY       BOUNDARY        BOUNDARY
```

**Key Principles:**
1. Each block is a self-contained mini-composition
2. Shift operations stay within the active block
3. Content that would overflow is truncated (with warning)
4. Blocks can be independently reset to chord defaults
5. Block duration changes shift downstream blocks (existing functionality)

### Implementation Phases

#### Phase 1.1: Block-Based Bass Shift Operations
**Files to modify:** `compositionState.js`, `noteEditor.js`

**New Functions to Create:**
```javascript
// In compositionState.js
insertBassNoteWithShift(chordIndex, unitPosition, durationUnits, pitches, options)
deleteBassNoteWithShift(chordIndex, unitPosition)

// These mirror the treble versions but operate on bassBlockSequence.blocks[chordIndex]
// instead of trebleBlockSequence.blocks[0]
```

**Key Differences from Treble:**
- Treble: Single block, shifts affect entire composition
- Bass: Per-chord blocks, shifts stay within that chord's block

**Boundary Enforcement:**
```javascript
// When shift would push content past block end:
if (newEndUnit > block.totalUnits) {
    // Option 1: Truncate with warning
    showWarning(`Note truncated to fit within ${chordName} block`);
    durationUnits = block.totalUnits - unitPosition;

    // Option 2: Prevent operation
    // showError(`Cannot shift - would overflow ${chordName} block`);
    // return false;
}
```

#### Phase 1.2: Block Reset/Revert Functionality
**Files to modify:** `compositionState.js`, `ProgressionController.js`

**New Function:**
```javascript
// Reset a bass block to its auto-generated default
resetBassBlockToDefault(chordIndex) {
    const chord = this.getChordAtIndex(chordIndex);
    const block = this.bassBlockSequence.blocks[chordIndex];

    // Clear all units
    block.clearAllUnits();

    // Re-generate default bass pattern based on chord and current settings
    this.generateDefaultBassForBlock(chordIndex, chord);

    // Mark as auto-generated again
    block.autoGenerated = true;

    // Re-render to measures
    this.renderBassBlocksToMeasures();
}
```

**UI Integration:**
- Add "Reset to Default" button on chord card's bass section
- Or right-click context menu on bass notes

#### Phase 1.3: Multi-Voice Support Per Block
**Files to modify:** `buildingBlock.js`, `compositionState.js`

Each bass block should support Voice 1 and Voice 2 independently:
```javascript
// Block structure enhancement
class BassBlock {
    voices: [
        { units: [...] },  // Voice 1
        { units: [...] }   // Voice 2
    ]
}
```

**Note:** This mirrors the treble limitation where multi-voice disables block sync. For bass, we'd need to decide:
- Option A: Same limitation (multi-voice = measure-based)
- Option B: True per-voice unit arrays (more complex but cleaner)

## Part 2: Dual Selection Model

### Concept: Cursor vs Container

```
┌─────────────────────────────────────────────────────────────────┐
│  MEASURE SELECTION (Cursor Position)                            │
│  - Where the next note will be placed                           │
│  - Works the same for treble and bass                           │
│  - Visual: Highlighted measure background                       │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│  BLOCK SELECTION (Editing Container) - BASS ONLY               │
│  - Derived automatically from cursor position                   │
│  - Defines boundary for shift operations                        │
│  - Visual: Shaded region showing block extent                   │
│  - Info display: "Editing: Am (4 beats)"                        │
└─────────────────────────────────────────────────────────────────┘
```

### State Management

**New State Variables:**
```javascript
// In compositionState.js or a new selectionState.js
const selectionState = {
    // Existing
    selectedMeasureIndex: 0,

    // New for bass
    activeBassBlockIndex: null,  // Derived from cursor position

    // New for clarity
    activeStaff: 'treble' | 'bass' | null,  // Which staff is being edited
};
```

**Derivation Logic:**
```javascript
function updateActiveBassBlock(measureIndex, beatInMeasure) {
    const absoluteBeat = measureIndex * beatsPerMeasure + beatInMeasure;
    const segment = compositionState.getChordSegmentForBeat(absoluteBeat);

    if (segment) {
        selectionState.activeBassBlockIndex = segment.chordIndex;

        // Also highlight the corresponding chord card
        highlightChordCard(segment.chordIndex);
    }
}
```

### Visual Feedback

#### Block Boundary Indicators
**File to modify:** `grandStaff.js`

```javascript
function drawBlockBoundaries(ctx, measures, chordSegments, activeBlockIndex) {
    for (const segment of chordSegments) {
        const startX = beatToX(segment.startBeat);
        const endX = beatToX(segment.startBeat + segment.durationBeats);

        // Draw subtle vertical lines at block boundaries
        ctx.strokeStyle = 'rgba(100, 100, 100, 0.3)';
        ctx.setLineDash([4, 4]);
        ctx.beginPath();
        ctx.moveTo(startX, bassStaffTop);
        ctx.lineTo(startX, bassStaffBottom);
        ctx.stroke();

        // Highlight active block
        if (segment.chordIndex === activeBlockIndex) {
            ctx.fillStyle = 'rgba(59, 130, 246, 0.1)'; // Light blue
            ctx.fillRect(startX, bassStaffTop, endX - startX, bassStaffHeight);
        }
    }
}
```

#### Block Info Display
**Location:** Above the bass staff or in a status bar

```
┌────────────────────────────────────────────────┐
│ Bass Block: Am (Block 2) │ 4 beats │ 2/4 used │
└────────────────────────────────────────────────┘
```

## Part 4: Click Ambiguity Resolution

### The Problem
The area between bass and treble staves (around middle C) is ambiguous:
- User clicks intending to add B3 to treble
- System interprets as D4 in bass (or vice versa)

### Solution: Explicit Staff Selection + Smart Fallback

#### Primary: Staff Selection Dropdown
User explicitly chooses which staff to edit. This becomes the "sticky" selection.

#### Secondary: Smart Detection with Confirmation
When in "Auto-detect" mode and click is ambiguous:

```javascript
function handleAmbiguousClick(clickY, staffPositions) {
    const distanceToTreble = Math.abs(clickY - staffPositions.trebleBottom);
    const distanceToBass = Math.abs(clickY - staffPositions.bassTop);

    // If clearly closer to one staff (>20px difference), use that
    if (Math.abs(distanceToTreble - distanceToBass) > 20) {
        return distanceToTreble < distanceToBass ? 'treble' : 'bass';
    }

    // Ambiguous - show quick picker
    showStaffPicker(clickX, clickY, (choice) => {
        if (choice === 'treble') {
            addNoteToTreble(/* ... */);
        } else {
            addNoteToBass(/* ... */);
        }
    });
}
```

#### Quick Picker UI
Small popup that appears at click location:
```
        ┌───────────────┐
        │  ↑ Treble     │
   ●────┤               │
        │  ↓ Bass       │
        └───────────────┘
        (click location)
```

#### Keyboard Modifiers (Power Users)
- `Shift+Click` = Force treble
- `Ctrl+Click` = Force bass
- Regular click = Use selected staff or auto-detect

## Part 6: Technical Details

### New State Structure

```javascript
// compositionState.js additions
class CompositionState {
    // Existing
    bassBlockSequence: BuildingBlockSequence;
    trebleBlockSequence: BuildingBlockSequence;

    // New
    editingState: {
        activeStaff: 'treble' | 'bass' | null,
        activeBassBlockIndex: number | null,
        staffSelectionMode: 'treble' | 'bass' | 'auto',
    }
}
```

### Key Function Signatures

```javascript
/**
 * Insert a bass note with shift within the specified block
 * @param {number} chordIndex - Which bass block (0-indexed)
 * @param {number} unitPosition - Position within block (0 to totalUnits-1)
 * @param {number} durationUnits - Duration in units (48 units per beat)
 * @param {string[]} pitches - Array of pitch strings e.g. ['C2', 'G2']
 * @param {Object} options - Additional note properties
 * @returns {Object} - { success: boolean, truncated: boolean, message: string }
 */
insertBassNoteWithShift(chordIndex, unitPosition, durationUnits, pitches, options) {
    const block = this.bassBlockSequence.blocks[chordIndex];
    if (!block) return { success: false, message: 'Invalid block index' };

    // Check if shift would overflow
    const wouldOverflow = this.checkBassShiftOverflow(chordIndex, unitPosition, durationUnits);

    if (wouldOverflow.overflow) {
        // Truncate to fit
        durationUnits = wouldOverflow.maxDuration;
        // Could also show warning here
    }

    // Perform the shift and insert (similar to treble logic)
    block.shiftUnitsForward(unitPosition, durationUnits);
    block.setNote(unitPosition, durationUnits, pitches, options);

    // Re-render to measures
    this.renderBassBlocksToMeasures();

    return {
        success: true,
        truncated: wouldOverflow.overflow,
        message: wouldOverflow.overflow ? 'Note truncated to fit block' : ''
    };
}
```

### Block Boundary Detection

```javascript
/**
 * Get the bass block that contains the given absolute beat position
 * @param {number} absoluteBeat - Beat position from start of composition
 * @returns {Object} - { chordIndex, block, beatInBlock, remainingBeats }
 */
getBassBlockForBeat(absoluteBeat) {
    let currentBeat = 0;

    for (let i = 0; i < this.bassBlockSequence.blocks.length; i++) {
        const block = this.bassBlockSequence.blocks[i];
        const blockEndBeat = currentBeat + block.beats;

        if (absoluteBeat >= currentBeat && absoluteBeat < blockEndBeat) {
            return {
                chordIndex: i,
                block: block,
                beatInBlock: absoluteBeat - currentBeat,
                remainingBeats: blockEndBeat - absoluteBeat,
                totalBeats: block.beats
            };
        }

        currentBeat = blockEndBeat;
    }

    return null; // Beat is past end of all blocks
}
```

## Part 7: Migration & Backwards Compatibility

### Data Migration
- No data structure changes required for existing progressions
- New `editingState` is transient (not saved)
- Existing `bassBlockSequence` structure remains the same

### Behavior Changes
| Action | Current Behavior | New Behavior |
|--------|-----------------|--------------|
| Shift+Arrow in bass | May not work or bleeds across blocks | Works within active block only |
| Click in ambiguous zone | Guesses based on Y position | Shows picker or uses selected staff |
| Add note past block end | Confusing errors | Clear truncation warning |
| Delete in bass | May desync block/measure | Properly updates block |

Could introduce feature flags for gradual rollout:

const FEATURES = {
