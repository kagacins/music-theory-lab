# Phase 4.4 Notation System Migration Status

## Overview

This document describes the current state of migrating from the legacy canvas-based notation renderer to the new VexFlow-based professional notation system (grand staff with treble and bass clefs).

## Goal

Unify the legacy `renderInteractiveMelodyStaff()` system with the new `NotationComposer` class, bringing over all integrated features:
- Measure highlighting (blue border for selected, yellow background for playing)
- Bi-directional sync between notation measure selection and chord progression cards
- Red highlighting for actively playing notes during playback
- Bass auto-fill with blue note coloring (only auto-generated notes, not chord notes)
- Harmonic tone coloring and tooltips for melody notes
- Click-to-play functionality

## Architecture

### Key Files

| File | Purpose |
|------|---------|
| `src/modules/notation/notationInit.js` | Entry point - `initEnhancedNotation()` creates NotationComposer |
| `src/modules/notation/composerIntegration.js` | `NotationComposer` class - main integration hub |

| `src/modules/audio/melodyGenerator.js` | Playback engine - calls window highlighting functions |
| `src/modules/integration/melodyComposerBridge.js` | Syncs progression data to compositionState |
| `src/modules/state/compositionState.js` | Central state for notation data |
| `src/modules/ui/tabs.js` | Tab activation - calls initialization in correct order |

### Data Flow

1. **Progression Builder** creates chord progression
2. **melodyComposerBridge** syncs progression to `compositionState` (including bass generation)
3. **NotationComposer.syncFromProgression()** reads from compositionState and populates `measureManager`
4. **NotationComposer.render()** calls `renderGrandStaffSystem()` with highlighting state
5. **grandStaff.js** renders VexFlow notation with colors and highlights

### Initialization Order (in tabs.js)

```javascript
// When melody tab is activated:
1. initEnhancedNotation()         // Creates NotationComposer, exports window functions
2. initMelodyComposerBridge()     // Initializes bridge
3. syncProgressionToMelodyComposer() // Populates compositionState with bass notes
4. refreshNotationFromProgression()  // Re-syncs notation with updated data
```

### Window Function Exports

The NotationComposer exports these functions to window for external access:

```javascript
window.setNotationSelectedMeasure(index)    // Blue border
window.setNotationActiveMeasure(index)      // Yellow background
window.addNotationActiveNote(noteId)        // Red note (format: "measureIndex-beat-pitch")
window.removeNotationActiveNote(noteId)     // Remove red
window.stopNotationPlaybackHighlighting()   // Clear all highlights
window.isNotationInitialized()              // Check if system is active
window.refreshNotationFromProgression()     // Re-sync and render
```

## What Has Been Implemented

### 1. Harmonic Tone Coloring (Treble Only)
- **File**: `grandStaff.js` - `applyNoteColoring()` function
- Melody notes in treble clef are colored based on chord tone analysis
- Bass clef notes are excluded from harmonic coloring (they stay black or blue if auto-generated)
- Uses `analyzeChordTone()` from `chordToneAnalyzer.js`

### 2. Auto-Generated Bass Notes (Blue Coloring)
- **File**: `grandStaff.js` - `applyNoteColoring()` function
- When `isAutoGeneratedBass` flag is true, bass notes are colored blue (#3B82F6)
- Regular chord notes in bass remain black
- Flag is set in `syncFromProgression()` when reading from compositionState

### 3. Measure Highlighting Infrastructure
- **File**: `grandStaff.js` - `drawMeasureHighlight()` function
- Yellow background (`rgba(255, 200, 0, 0.25)`) for `activeMeasureIndex >= 0`
- Blue border (`rgba(59, 130, 246, 0.8)`) for `selectedMeasureIndex` when not playing

### 4. Note Highlighting Infrastructure
- **File**: `grandStaff.js` - `applyNoteColoring()` function
- Red color (#EF4444) for notes in the `activeNotes` Set
- Note ID format: `"measureIndex-beat-pitch"` (e.g., "0-0-C4")

### 5. Bi-directional Sync
- **File**: `composerIntegration.js` - `setupProgressionSync()`
- Listens for `chordCardSelected` events from progression builder
- Fires `notationMeasureSelected` events when measure is selected in notation

### 6. Playback Integration Points
- **File**: `melodyGenerator.js`
- Added calls to `window.setNotationActiveMeasure()` in:

  - `playAllMeasures()` (around line 5287)
  - `playMeasure()` (around line 5474)
- Added calls to `window.addNotationActiveNote()` / `window.removeNotationActiveNote()` for:
  - Melody notes during playback
  - Bass notes during playback
  - Chord notes during playback
- Added calls to `window.stopNotationPlaybackHighlighting()` in:
  - `stopMeasurePlayback()` (around line 4936)
  - `playAllMeasures()` end callback (around line 5356)

## Outstanding Issues

### 1. Yellow Measure Highlighting During Playback NOT WORKING

**Symptoms**:
- Yellow appears when clicking a measure to play it (single measure playback works)
- Yellow does NOT update during continuous playback (playAllMeasures)

**Likely Causes**:
- `Tone.Draw.schedule()` may not be firing correctly during Transport playback
- The scheduled callback may be running but render() might not be completing
- Possible timing issues with multiple rapid render() calls

**Debug Approach**:
- Add console.log in `setActiveMeasure()` to verify it's being called
- Check if `Tone.Transport` is actually running during playAllMeasures
- Verify the `measureIndex` value being passed is correct

**Relevant Code** (melodyGenerator.js ~5287):
```javascript
Tone.Draw.schedule(() => {
    if (window.isNotationInitialized && window.isNotationInitialized()) {
        if (window.setNotationActiveMeasure) {
            window.setNotationActiveMeasure(measureIndex);
        }
    }
}, time);
```

### 2. Red Note Highlighting During Playback NOT WORKING

**Symptoms**:
- Notes don't turn red when playing

**Likely Causes**:
- Note ID format mismatch between melodyGenerator and grandStaff
- The `activeNotes` Set may not be passed correctly to renderer
- Beat values may not match between playback and rendering

**Debug Approach**:
- Log the noteId being added in melodyGenerator
- Log the noteId being checked in `applyNoteColoring()`
- Verify the `beat` values match

**Note ID Format**:
- Generated in melodyGenerator: `${measureIndex}-${noteBeat}-${note.pitch}`
- Checked in grandStaff: `${measureIndex}-${beat}-${pitch}`
- The `beat` comes from `note.beat || 0`

### 3. Auto-Generated Bass Notes Not Rendering Visually

**Symptoms**:
- Audio playback uses correct auto-generated bass patterns
- Visual notation still shows chord notes instead of pattern notes

**Likely Causes**:
- `syncFromProgression()` may not be finding bass notes in compositionState
- The `autoGenerated` flag may not be set correctly
- The compositionState may not have the bass notes when syncFromProgression runs

**Debug Approach**:
- Log `foundBassInState` in syncFromProgression
- Check if `compositionState.getMeasure(i).notation.bass.voices[0].notes` has data
- Verify the initialization order is correct

**Relevant Code** (composerIntegration.js ~289):
```javascript
if (this.compositionState && this.compositionState.getMeasureCount() > i) {
    const stateMeasure = this.compositionState.getMeasure(i);
    if (stateMeasure && stateMeasure.notation && stateMeasure.notation.bass) {
        const bassVoices = stateMeasure.notation.bass.voices;
        if (bassVoices && bassVoices[0] && bassVoices[0].notes && bassVoices[0].notes.length > 0) {
            // Use bass notes from compositionState
            measureData.bassNotes = bassVoices[0].notes
              .filter(note => note.type !== 'rest')
              .map(note => ({...}));
            measureData.isAutoGeneratedBass = stateMeasure.notation.bass.autoGenerated || false;
        }
    }
}
```
